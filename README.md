# 古典音樂系統聆聽課程 · 互動網站

把 24 週的古典音樂自學教程做成可互動的單頁網站：每首曲目都附**經過挑選的著名版本**，依 **Hi-Res → Hi-Fi → 歷史錄音** 排序，可一鍵連往 KKBOX 搜尋。

## 直接使用

```bash
# 方式一：直接用瀏覽器開啟
open index.html

# 方式二：起一個本機伺服器
python3 -m http.server 8000   # 然後開 http://localhost:8000
```

不需要安裝任何東西，沒有相依套件、沒有 build step。

## 音質標記怎麼判定

網站上的三種標記是**依錄音年代與發行廠牌所作的推估**，不是 KKBOX 的即時資料：

- **Hi-Res 優先** — 近年數位錄音，或大廠已發行 24bit 高解析重製（BIS、Channel Classics、Linn、Pentatone、LSO Live、近年的 DG / Decca / Harmonia Mundi 等）
- **Hi-Fi 無損** — 類比時代名盤之數位重製，通常為 16bit/44.1kHz
- **歷史錄音** — 單聲道或早期立體聲。收錄理由為詮釋史地位，不以音質取勝

實際請以 KKBOX App 內顯示的音質標記為準。App 內需先到「設定 → 音質」把串流音質調到最高。

## KKBOX 連結

搜尋網址格式為：

```
https://www.kkbox.com/{region}/{lang}/search?q={關鍵字}
```

此格式經實測確認可用。開發環境連不上 kkbox.com（網路政策 403），無法自行驗證，
因此曾以候選清單逐一測試，過程中排除：

| 格式 | 結果 |
|---|---|
| `/{region}/{lang}/search/all/{q}/1` | 404，路徑不存在 |
| `/{region}/{lang}/search?word={q}` | 搜尋頁正常開啟但關鍵字為空 |

格式寫在 `assets/app.js` 的 `searchUrl()`，若日後 KKBOX 改版只需改這一個函式。
地區（tw / hk / sg / my / jp）與語言（tc / sc / en / ja）可在設定中調整。

每個版本的搜尋字串直接顯示在該版本下方，點下去會搜什麼一目瞭然，
也方便自行調整後貼進 App。字串遵循課程 §2.1 的「作曲家 + 作品 + 演奏者」三段式。

### 釘選正式連結（手機直接開 App）

搜尋連結沒有曲目 ID，無法觸發 Universal Link。若要點一下就跳進 KKBOX App 播放，
需要帶 ID 的正式網址：

```
https://www.kkbox.com/tw/tc/album/{id}     ← App「分享 → 複製連結」得到的網址
https://kkbox.fm/{id}                       ← 短網址，同樣可用
```

在 App 找到專輯 → 分享 → 複製連結 → 回網站按該版本的 **🔗 貼上分享連結**。
釘選後按鈕變成 **▶ 開啟 App**，直接跳轉不再經過搜尋。

釘選連結有兩層，解析順序為 **本機 → 內建 → 搜尋連結**：

| 層 | 存放位置 | 範圍 |
|---|---|---|
| 🔗 本機 | 瀏覽器 localStorage | **只有那台裝置的那個瀏覽器**。電腦上釘的手機看不到 |
| 🔗 內建 | `assets/data-links.js`（隨 git 部署） | **所有裝置** |

把本機釘選變成跨裝置共用：⚙ 設定 →「複製全部（JSON）」→ 貼進 `assets/data-links.js` → push。
`build.js` 會在打包時檢查每個 key 都對得上實際的搜尋字串，打錯字會直接讓建置失敗。

### 批次解析正式連結

手動釘選之外，也可用 KKBOX Open API 一次解析全部 305 個版本：

```bash
export KKBOX_CLIENT_ID=...      # https://developer.kkbox.com/ 免費申請
export KKBOX_CLIENT_SECRET=...
node tools/resolve-kkbox.mjs --dry-run --limit=10   # 先試跑
node tools/resolve-kkbox.mjs                        # 正式執行
node build.js
```

高信心的結果寫入 `assets/data-links.js`；比對不確定的改列入
`tools/review-needed.json` 附前三名候選供人工挑選——**寧可攔截也不寫錯**，
錯誤的連結會把使用者導到錯誤的錄音，比留白更糟。

腳本無外部相依，API 契約取自 KKBOX 官方 Python SDK。詳見 [HANDOFF.md](HANDOFF.md)。

```bash
node build.js   # → dist/index.html（約 172 KB，可離線使用／單檔分享）
```

### 新增或修改版本推薦

編輯 `assets/data-works-*.js`，每個版本的欄位為：

```js
{
  p: "演奏者 / 樂團",
  l: "廠牌", y: 1974,
  qa: "hires",              // hires | hifi | historic
  t: ["ref", "modern"],     // ref 公認代表版 / period 古樂器 / modern 現代樂器
                            // entry 入門友善 / narrated 附旁白
  q: "KKBOX 搜尋字串",
  w: "推薦理由"
}
```

搜尋字串遵循課程 §2.1 的「作曲家 + 作品 + 演奏者」三段式。`build.js` 會在打包時檢查：

- 每個字串都含作曲家姓氏（缺了會搜到同名作品）
- 同一曲目底下沒有兩個版本共用同一字串（否則不同版本會搜到同一批結果）

任一項不合格即建置失敗。例外情況（如 Pärt 的《Alina》《Tabula Rasa》以專輯名搜尋較準）
仍需含作曲家，但不強制含演奏者姓名。

## 課程設計的參考來源

主幹沿用原教程（時期軸 + 聆聽能力工具）。以下維度參考自
[焦元溥《37 堂古典音樂課》](https://sat.cool/course/19) 的「時期／地理／樂器」三軸
與「故事 × 聆賞 × 生活」設計：

- **地理軸** — 新增「音樂地圖」附錄，把曲目按城市重新排列一次
- **樂器軸** — 新增「樂器的演變」附錄。許多被歸因於「時代風格」的聽感差異其實是
  樂器構造改變的結果；此頁把這條線獨立拉出來，5 條演變線（鍵盤／弦樂／樂團編制／
  管樂／人聲）各附一個使用課程既有曲目的對比聆聽
- **生活軸** — 曲目層級新增「你可能在哪裡聽過」，只收錄具體可查證的關聯
  （例：《給愛麗絲》＝台灣垃圾車、Bach BWV 846 前奏曲＝Gounod《聖母頌》的伴奏、
  Dvořák 第 9 號第二樂章＝〈念故鄉〉、Beethoven 第 9 號〈歡樂頌〉＝歐盟盟歌、
  Mozart《費加洛》〈Sull'aria〉＝《刺激 1995》）。刻意排除「常用於電影廣告」
  這類無法查證的模糊敘述

延伸影片來自 [音樂家的無聊人生 Musecow](https://www.youtube.com/@musecow)（海牛／許崴）。
每週的主要入口為<b>頻道內搜尋連結</b>（官方網址格式，不會失效）；另有 12 支經公開搜尋
驗證的直接影片連結，標示為「直接連結」，若失效可回退到頻道搜尋。

## 檢視結構

課程分 24 週、預期使用 6 個月，每次回訪只需要一週的內容。因此**預設一次只渲染
當前檢視**，而非把整份課程放在同一份文件裡：

| | 改版前 | 改版後 |
|---|---|---|
| DOM 節點 | 8,944 | **564**（單週） |
| 文件高度（桌機） | 40,077px＝44.5 螢幕 | **2,270px＝2.5 螢幕**（單週） |
| 文件高度（手機） | 59,773px＝70.8 螢幕 | 2,708px＝3.2 螢幕（單週） |
| 首頁到第 1 週 | 7,995px＝8.9 螢幕 | 0（首頁即為「本週」卡片） |

- **URL hash 為單一真實來源**：`#week-5`、`#p-geo`、`#all`。可加書籤、可建手機捷徑，
  瀏覽器上一頁／下一頁自動可用。未知的 hash 落回首頁。
- **`#all`（顯示全部）**保留完整長頁面，供一路瀏覽與列印。
- **搜尋改為資料層搜尋**（原本是對已渲染的 DOM 加 `.hidden`，單週檢視下會失效）。
  結果會標明每首曲目屬於第幾週並可直接跳轉——這是原本做不到的。

「本週」入口卡片由 `S.done` 推算最小的未完成週次，顯示該週的核心必聽第一首
（即課程定義的「15 分鐘最低標準」）與必做任務，勾選狀態與週檢視同步。

### 概念區塊可摺疊

課程要求每首曲目重複聽 4–6 次，也就是同一週會回訪多次；概念說明只在第一次要讀，
之後每次都得滑過去才看到曲目。所以「時期概覽／模組目標／本週核心概念／表格／
辨識線索」統一包進一個可摺疊區（`<details class="theory">`）：

| 第 8 週（內容最多的一週） | 展開 | 收起 |
|---|---|---|
| 概念區塊本身 | 802px | **49px** |
| 週標題 → 第一個曲名（桌機） | 933px | **180px** |
| 週標題 → 第一個曲名（手機） | 1,382px | **212px** |

- **預設展開**——第一次讀概念是課程設計的一部分，不預設藏起來。
- 收起狀態**逐週記憶**在 `S.theory`，收起第 8 週不影響第 5 週。
- 用原生 `<details>` 而非自製摺疊，因為 `<summary>` 本身就可聚焦、可用 Enter／Space
  開合，不需要自己補 ARIA。
- 列印時 `beforeprint` 會把摺疊區展開（收起的 `<details>` 內容不會列印），
  但 `.ans`（答案）除外——任務本身就要求準備紙筆，印出來作答時不該連答案一起印上去。

`wk.flag`（如第 8 週「全課程最關鍵的單一單元」）留在標題列，不進摺疊區——
那是要讓人看見的優先級提示。

### 對照表（答案）

第 1 週的任務要求「不看說明作答，聽完後對照計算正確率」，但原本站上**沒有任何一張
對照表**，任務等於做不完。掃過全部 24 週後，這類「要求核對／計數／對照某份資料，
而那份資料不存在」的任務共 **12 項**，散在 9 個週次。全部補上曲目層級的 `answer` 欄位：

| 週 | 曲目 | 對照什麼 |
|---|---|---|
| 1 | Britten《青少年管弦樂入門》 | 主題 6 次 + 變奏 A–M 共 13 段，判斷點 19 個 |
| 1 | Prokofiev《彼得與狼》 | 7 個角色的樂器對應 |
| 1 | Saint-Saëns《動物狂歡節》 | 14 段的主角樂器 |
| 3 | Haydn 第 94 號《驚愕》 | 主題 + 4 變奏 + 尾聲，各變奏改了哪個參數 |
| 5 | Vivaldi《四季》 | 〈春〉第一樂章 ritornello 段落地圖；〈夏〉第三樂章的十四行詩原文與中譯 |
| 5 | Bach 布蘭登堡第 5 號 | 大鍵琴獨奏的位置與長度（65 小節） |
| 6 | Bach BWV 846 賦格 | 主題約 24 次，以及**為什麼你數不到 24** |
| 8 | Mozart K. 550 | 奏鳴曲式地圖：第一／第二主題、發展部、再現部、尾聲（附小節數） |
| 13 | Schubert《魔王》 | 四個角色的音區與語氣；八段歌詞大意 |
| 14 | Berlioz《幻想交響曲》 | idée fixe 在**五個樂章**各自的變形 |
| 14 | Mussorgsky《展覽會之畫》 | 16 曲全表；〈漫步〉次數**依版本而不同** |
| 16 | Puccini《波希米亞人》 | 四幕劇情摘要 |
| 17 | Smetana〈莫爾道河〉 | 10 個段落地圖（Smetana 自己寫的解說） |
| 18 | Ravel《波麗露》 | 18 次旋律的主奏樂器 |

設計原則：

- **`<details class="ans">` 預設收起**——先看到答案就沒有練習效果了。位置緊接在對應的
  聆聽任務下方，不是放在頁尾。
- **不列時間碼，列順序與聽覺線索。** 同一首曲子各版本演奏時間差很多，寫死時間碼
  反而會害人對錯位置。要對樂譜的地方改附小節數。
- **答案不確定時就說不確定。** 例如 BWV 846 賦格的主題次數受 stretto 影響難以聽數，
  對照表直接說明「目標是自己三次計數一致，不是命中某個數字」；《展覽會之畫》的
  〈漫步〉次數在鋼琴原版是 5 次、Ravel 管弦樂版是 4 次，也直接標出來。
- **參考資料不當劇透**：歌詞大意與劇情摘要改用 `label` 標為「📖 建議先讀」，
  因為任務本身就要求先讀。
- 對應的任務敘述也一併改寫，明確指向站內的對照表，不再要求使用者自己去查外部資料。

## 鍵盤與無障礙

| 項目 | 說明 |
|---|---|
| **曲目可用鍵盤展開** | 曲名是 `<button class="ttl" aria-expanded>`，不是 `<div>`。原本無法聚焦，等於鍵盤使用者拿不到任務與播放連結 |
| **可見的焦點框** | `:focus-visible` 描邊（滑鼠點擊不會出現）。`.play` 是深色底按鈕，改用 `outline` + `box-shadow` 雙層描邊以在淺色與深色主題下都看得見 |
| **搜尋框** | 輸入框本身無邊框，焦點框由 `.search:focus-within` 顯示在整個膠囊上 |
| **`prefers-reduced-motion`** | 關閉平滑滾動並把所有 transition／animation 壓到最小 |
| **觸控目標** | 手機上主要按鈕與 `<summary>` 皆 ≥ 44px |

`transition:.15s` 這種簡寫等於 `transition:all`，會讓焦點框淡入、Tab 快速切換時
明顯落後，所以 `.iconbtn`／`.navitem`／`.play`／`.workhd`／`.star` 都改成明確列出
要過渡的屬性。

完整鍵盤路徑（只用 Tab／Enter／Space）：側邊欄週次 → 搜尋框 → 概念區開合 →
★ 收藏 → 展開曲目 → 勾選聆聽任務 → 播放連結，每一步都有可見焦點框。

## 版本清單的語意

同一首曲目下列出的多個版本是**同一首曲子的不同演出（皆為全曲，非片段）**，
使用者<b>只需選一個聽</b>。介面在版本清單上方明確標示這一點——早期版本沒有說明，
容易被誤讀為「一首曲子的數個段落」。

曲目層級的三個文字欄位各有分工，**不重複彼此、也不重複任務**：

| 欄位 | 層 | 回答什麼 |
|---|---|---|
| `bg` 作品背景 | 【史】【析】 | 這首曲子是在什麼情況下寫出來的、有什麼爭議 |
| `life` 你可能在哪裡聽過 | 【史】 | 具體可查證的生活關聯 |
| `pick` 編者建議 | 【選】 | **要聽哪個版本、哪個樂章、聽多久** |

`pick` 原本有 27 筆寫成了該週任務的複述——同一段文字在畫面上相隔幾公分出現兩次，
既是雜訊，也稀釋了刻意放在播放鈕正上方的任務框。已全部改寫為真正的版本／樂章選擇
建議（例：「重點在末樂章，只有 15 分鐘就直接聽第四樂章」「必須一次聽完，跳著聽等於沒聽」）。

`assets/data-weeks.js` 的 `tw` 欄位把每一項聆聽任務對應到它所屬的曲目，
渲染時任務會出現在該曲目的播放按鈕正上方。原本任務統一放在該週最下方，
使用者往往點了 KKBOX 連結就離開，根本沒看到「這次要聽什麼」——那等於架空了
本課程「每次聆聽只設定一個注意力標的」的核心方法。兩處的勾選狀態同步。

## 內容性質

課程內容依三層分類標記：**【史】史實層**（可查證的客觀事實）、**【析】分析層**（學界通說）、**【選】策展層**（編者的教學判斷，無客觀對錯）。

**全部曲目選擇與版本推薦皆屬【選】層。** 若指定版本在 KKBOX 無法取得，改用平台上任何其他版本仍可完成全部聆聽任務。
